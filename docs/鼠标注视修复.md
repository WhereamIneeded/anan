# 鼠标注视修复：1.0.3

## 反馈与原因

用户反馈：鼠标对焦时低头、转头仍有显示异常。截图中侧下方注视的嘴和下巴被胸毛盖住，脸部不完整。

将原方向素材与播放器输出逐一比较，确认原素材的面部完整。问题发生在程序合成：原 `stabilize_look` 在运行画布第 118～128 行混合头部和静止身体，低头时嘴和下巴伸到这条线下方，因此被固定胸毛覆盖。播放器最后的 `keep_static_body` 又从第 128 行复制静止身体，再次截断面部。只修改其中一个位置不能完整修复。

此前测试强调第 128 行以下的身体不变化，却没有检查低头面部完整性，未能捕获这个问题。

## 本次修改

- 使用已批准的原方向素材，保留完整头部和颈部；没有新增猫咪姿势或覆盖历史素材。
- 将注视的羽化衔接区移到第 152～168 行，低头的嘴和下巴保持原方向帧的像素。
- 注视时只在第 168 行以下固定下半身。待机眨眼继续使用原第 128 行边界，以保留静止身体稳定效果。
- 鼠标移开回正时，在短过渡结束前继续保留注视所需空间，避免过渡中被待机的身体复制再次截断。
- 保留单击跳、拖动不误触和悬停不跳的交互，不改变方向素材及方向识别规则。

以上坐标均为 256×256 运行画布坐标，实际显示沿用统一缩放。

## 验证

五个低头方向和实际悬停播放器的面部回归检查，修复前失败，修复后通过。新增检查还覆盖：100、220、400 三种大小下的全部 16 个注视方向、完整面部、稳定下半身、悬停不跳，以及低头回正的中间画面。

运行 `python scripts/验证鼠标注视.py --output <输出目录>`，可通过模拟光标位置和窗口自身的 `paintEvent` 导出深浅背景的十六方向图、鼠标注视 GIF、低头静帧及三种大小的实际绘制对照。脚本使用临时偏好，不改用户设置。

验证环境为 Linux、Python 3.12.14、Qt 6.12.0 的 `offscreen` 平台。新版 Windows EXE 构建与用户真实桌面体验仍需在 Windows 验收，不能用自动检查替代。
