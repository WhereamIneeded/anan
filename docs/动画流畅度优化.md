# 动画流畅度优化：1.0.1

## 反馈和执行计划

2026 年 10 月 23 日，用户确认独立桌面版可以运行，但与原 Pets 相比，静止时身体稍有闪烁，挠耳动作明显卡顿。本次只优化这两个现象及其直接相关的播放问题，保留原 Pets、原始资料和已有交互。

1. 检查素材、帧时长、实际计时与绘制开销，区分姿势跳变和性能不足。
2. 用失败的回归测试覆盖静止身体、短过渡透明度、动作末尾、重复重绘和鼠标方向消抖，再实现修复。
3. 补足挠耳中间姿势；固定图集裁取的共同坐标，避免按每帧外轮廓重新居中。
4. 检查睡眠、单击、拖动和散步；构建新版并从远端版本验证独立目录运行。

## 根因证据

- 原静止动画六张全身图，每张190毫秒，约每秒5.26个姿势。身体区域相邻图像的RGB平均差约3.37～6.39；眨眼也重新绘制胸毛和身体，形成闪烁。
- 原挠耳八段播放只使用六个独立姿势，约每秒5.97个姿势。身体区域RGB平均差最高约29，轮廓与位置也变化，无法单靠增加窗口刷新解决。
- 默认粗精度计时器设为33毫秒，本机实际间隔中位数约47毫秒；精确定时器设为16毫秒后，实测中位数约15.99毫秒，P95约17毫秒。此为本机测量，不作为其他电脑的帧率保证。
- 实际绘制中位数约0.158毫秒，400像素平滑缩放约0.322毫秒；主要问题不是CPU绘图太慢。
- 旧播放器对非循环动作也取模，动作结束、控制器尚未切换时，重新绘制可能短暂采样回首帧。
- 旧注视图也逐张改变身体；鼠标在方向边界或窗口中心微动时，没有死区和迟滞，会放大跳变。

## 修复方式

- 静止时以同一张原坐姿为基底，只在羽化的双眼区域合成眨眼；每次眨眼前停留约3秒，闭眼过程短促。
- 注视只替换头部，身体保持同一基底；加入中心死区和方向边界迟滞。
- 使用16毫秒精确定时。先采样并缓存实际画面，只有画面变化时才请求重绘，重绘事件不自行推进动画时钟。
- 挠耳相邻姿势使用60毫秒短过渡，动作切换最多80毫秒。透明图先分别预乘权重再相加，防止普通半透明叠加让身体透底、变暗；不透明区域的实测颜色误差不超过1级。静止身体最后直接复制原像素，连半透明毛尖的舍入变化也去除。
- 非循环动作保持最后一帧；循环待机与睡眠仍正常循环。
- 散步按经过的时间累计位移，约30逻辑像素/秒，不随刷新率翻倍。
- 新挠耳素材由内置图像生成工具制作，保留中文提示、源图、透明运行帧与实际播放器预览。旧图和旧运行帧保留以便比较。

## 验证记录

新增十二项质量回归用例先失败后通过，全套28项通过，独立复核再次通过。悬停、单击、拖动和两种睡眠路线保持正常，散步在16和33毫秒刷新间隔下的速度一致。
