# 个性化猫咪代表姿势验证

本工具独立于现有安安桌宠，用用户自有猫咪照片验证七个代表姿势的身份一致性、透明背景与画面尺度。它不会更换当前安安、连接生产窗口、生成全部动画或导入角色。七张图片通过技术校验，也不代表真实猫咪身份、姿势质量与连续动画已经通过人工验收。

本次开发只进行了离线合成测试和本机 HTTP 协议测试，没有使用真实照片、真实密钥或产生 OpenAI 图片费用。真实接口权限、费用及生成效果尚待用户在自己的普通终端验证。离线合成测试预览明确标记“离线合成测试”，不能作为真实生成结果。

## 环境与输入

- 使用项目的 Python 开发环境，需要 Pillow；无需安装 OpenAI SDK。当前工具作为源码验证脚本运行，不随桌宠正式启动。
- 选择自己有权上传的单张猫咪静态照片，文件不超过 20 MiB，像素不超过 2400 万。照片先按 EXIF 纠正朝向，再转成不含元数据的 PNG，最长边限制为 2048 像素。联网只发送处理后的参考图，不发送本地原照文件。
- 原照按原始字节保存为任务目录中的 `原照.bin`，仅供本地核查。任务目录也会包含照片衍生图，应按个人资料妥善保存。
- 默认输出目录为项目 `build/个性化验证`，可用 `--output` 指定新的空目录。非空目录拒绝覆盖；输出不能位于安安素材目录，也不能覆盖输入照片。不要将用户照片、密钥、任务结果或预览提交到 Git。

## 逐张运行

在项目根目录打开 PowerShell。下列照片路径需要替换成用户自己的实际文件，输出默认位于 `build` 下。

```powershell
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py --help
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py prepare --photo 'C:\照片\我的猫咪.jpg'
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py preview
```

`prepare` 只复制照片与既有动作模板，创建七个“待生成”槽位，请求次数为零。`preview` 在未完成时显示“尚无合格结果”和各槽位状态，两者都不会联网。

```powershell
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py generate
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py preview
```

只有 `generate` 会联网，而且每次最多请求一张。优先使用当前进程环境变量 `OPENAI_API_KEY`。如果未设置，交互终端会隐藏询问密钥，密钥仅在该进程内存中使用；不要把密钥粘贴到聊天、脚本、命令行参数或仓库。终端无法关闭回显时会停止，不回退到明文输入。没有密钥的非交互终端会直接停止。工具不提供 `--key` 参数，也不保存密钥。

第一张固定为待机基准。检查其脸部、花色、毛长、眼色、体态与原照是否相符，且四肢、边缘与透明背景合理。技术校验无法替代这一步人工判断。满意后明确执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py accept
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py generate
```

`accept` 只确认已成功生成的待机基准，本身不联网。确认前再次执行 `generate` 会停止，不会请求第二张。确认后继续逐次运行 `generate`，直到其余六张全部完成，再运行 `preview`。全部完成后再次运行 `generate` 不会重复请求。

若自定义了 `--output`，后续每个命令都需要传入相同的任务目录。

## 七个固定姿势与参考关系

| 顺序 | 姿势标识 | 既有模板 | 用途 |
| --- | --- | --- | --- |
| 1 | `idle[0]` | `frames/idle/00.png` | 正面待机基准 |
| 2 | `look[4]` | `frames/look/04.png` | 一个方向的注视 |
| 3 | `look[12]` | `frames/look/12.png` | 另一方向的注视 |
| 4 | `waving[1]` | `frames/waving/01.png` | 招呼第一姿势 |
| 5 | `waving[2]` | `frames/waving/02.png` | 招呼第二姿势 |
| 6 | `eat_loop[1]` | `frames/eat_loop/01.png` | 低头进食姿势 |
| 7 | `supine_sleep[0]` | `frames/supine/03.png` | 仰卧熟睡姿势 |

首次请求传两张参考：处理后的用户猫咪照片、当前动作模板。后续请求增加第三张已确认的个性化待机基准。中文提示逐一说明各参考的角色：用户照片决定身份，安安模板只决定动作和构图，已确认基准保持后续身份和画风。提示明确禁止继承安安的长毛、蓝眼与花色，要求固定镜头、透明背景与稳定落地关系。

## 费用、失败与明确重做

正常流程共七次请求。本任务固定最多十次请求，额外三次只用于用户明确授权重做。工具不估算费用；实际收费以 OpenAI 账户记录为准。超时、服务错误、返回不合格图片和崩溃前已记录的请求都占用本地请求次数，不能据此断言服务没有计费。

每次请求前，工具先将“请求中”和递增后的次数写入 `任务.json`。请求中断或上次进程崩溃后，状态转为“结果未确认”，不会自动重发。请先查看已有文件与账户用量，再决定是否承担新一次请求的费用。失败或未知结果不会被连续运行 `generate` 自动跳过或重试。

明确重做分两步：

```powershell
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py retry --pose 'look[4]'
.\.venv\Scripts\python.exe .\scripts\验证个性化生成.py generate
```

`retry` 只将指定姿势重新置为“待生成”，本身不联网。历史尝试、原始图和提示仍保留。基准在任何后续姿势尚无请求时可以重做，重做会取消基准确认；已有后续请求时拒绝重做基准，以免混用不同身份，应保留旧任务另建任务。达到十次上限后不能继续授权或发送请求；不要编辑任务文件或计数规避上限。

同一任务使用进程级文件锁保护生成、确认、重做与预览。另一个终端同时操作会直接停止；系统会在进程退出或崩溃后释放锁。不要手动删除锁文件来绕过保护。

## 本地结果与验收范围

`任务.json` 用中文字段记录模型快照、提示版本、七槽状态、输入 SHA-256、次数及逐次尝试。照片、模板或已确认基准的校验不符时拒绝继续；模型或提示版本发生变化后，也拒绝将新请求混入旧任务。每次尝试分别保存：

- `提示.txt`：实际发送的中文角色与动作说明。
- `原始.png`：成功取得的原始响应图片，即使图片不合格也保留。
- `规范.png`：技术校验合格后，按完整 1024×1024 画布缩小到 256×256 的透明 PNG。
- 耗时、允许的整数用量字段、受限请求标识及结果状态，写入该次尝试记录。

技术校验要求图片可解码、确为 1024×1024 PNG、含透明通道、有完全透明像素及足够可见主体。全透明、全不透明、尺寸错误或损坏图片不会标为“已完成”。规范化不使用安安去绿规则，不按猫咪包围盒重新裁切或等高放大。预览导出 `预览/深浅对照.png` 与 `预览/姿势顺序.gif`，标签使用系统中文字体。顺序 GIF 只是七个代表姿势的依次展示，不能视为完整连续动画。

人工验收仍需检查身份一致性、不同姿势的身体比例、实际脚底位置、仰卧结构、毛发边缘，以及招呼两姿势是否能衔接。此阶段没有实现完整动作导入；应先确认真实少量样张达标，再决定下一阶段工作。

## 接口边界与离线验证

生产接口固定为 `https://api.openai.com/v1/images/edits`，模型固定 `gpt-image-2.5-sunburst-2026-09-08`；通过 JSON `images[].image_url` 发送 PNG 数据地址，固定透明背景、PNG、高质量、1024×1024、每次一张，不发送 `input_fidelity`。标准库 urllib 使用默认 TLS 校验与系统代理，套接字超时 180 秒，响应读取最多 32 MiB，禁止重定向且不自动重试。远端错误和原始网络异常不会进入用户错误说明或任务日志，任意远端用量字段也不会原样落盘。

协议依据：[图片编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)、[模型说明](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)。本机离线契约测试只能证明客户端请求与响应处理符合约定，不能证明当前账户已获得模型权限或真实生成质量通过。

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_image_service.py tests/test_personalization_probe.py --basetemp build/个性化测试
```

测试使用本地合成图、可注入假服务和 `127.0.0.1` HTTP 服务，不调用真实 OpenAI。测试结果与个人任务结果均应留在 `build` 下。
