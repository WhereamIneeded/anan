# 个性化代表动作验证实施计划

> 执行方式：使用superpowers:subagent-driven-development完成一个完整的验证工具任务，依次进行需求与质量审查。使用superpowers:test-driven-development先写失败测试。用户已确认OpenAI方案，不重复询问是否执行。

**目标：** 用用户主动提供的一张非安安猫照片、小批量OpenAI图片编辑请求，验证个性化姿势是否能用于现有桌宠；先交付可恢复、费用次数受控、不会泄露密钥的离线可测试工具。

**架构：** 独立的官方HTTP客户端负责一次编辑请求；验证任务负责照片、固定七姿势、基准确认、恢复与预览；中文脚本提供命令行入口。正式桌宠窗口、内置素材与版本均不改。真实生成依赖用户提供照片和在本机终端录入密钥，不用内置图像工具冒充该API已验证。

**技术栈：** 当前Python、标准库urllib及既有Pillow，不新增SDK或依赖；固定官方HTTPS接口`https://api.openai.com/v1/images/edits`，候选快照`gpt-image-2.5-sunburst-2026-09-08`。非流式JSON请求、多参考图data URL、透明PNG、1024×1024、high质量、n=1；不发送其他模型专有参数。

- [x] 步骤1：写失败测试。必须包含以下真实约束，不能只验证替身被调用。

```python
from io import BytesIO
from pathlib import Path

import pytest
from PIL import Image

from anan_pet.image_service import ImageResult, ServiceError
from anan_pet.personalization_probe import ProbeError, accept_base, generate_next, prepare_task


def prepare(tmp_path):
    photo = tmp_path / '试验照片.png'
    Image.new('RGB', (300, 300), 'orange').save(photo)
    output = tmp_path / '任务'
    prepare_task(photo, output, Path(__file__).resolve().parents[1] / 'assets')
    return output


def result():
    picture = Image.new('RGBA', (1024, 1024))
    picture.paste((180, 100, 60, 255), (300, 100, 700, 960))
    buffer = BytesIO()
    picture.save(buffer, format='PNG')
    return ImageResult(buffer.getvalue(), {'total_tokens': 10}, 'req_test')


class FakeService:
    def __init__(self):
        self.calls = 0

    def edit(self, prompt, images):
        self.calls += 1
        return result()


def test_preparing_a_photo_never_sends_a_request(tmp_path):
    import json
    output = prepare(tmp_path)
    state = json.loads((output / '任务.json').read_text(encoding='utf-8'))
    assert state['请求次数'] == 0
    assert len(state['姿势列表']) == 7
    assert (output / '参考.png').is_file()

def test_no_pose_generation_before_base_is_accepted(tmp_path):
    output = prepare(tmp_path)
    service = FakeService()
    generate_next(output, service)
    with pytest.raises(ProbeError, match='确认'):
        generate_next(output, service)
    assert service.calls == 1
    accept_base(output)
    generate_next(output, service)
    assert service.calls == 2

def test_unknown_network_result_is_not_retried(tmp_path):
    class TimeoutService(FakeService):
        def edit(self, prompt, images):
            self.calls += 1
            raise ServiceError('结果未确认', uncertain=True)

    output = prepare(tmp_path)
    service = TimeoutService()
    state = generate_next(output, service)
    assert state['姿势列表'][0]['状态'] == '结果未确认'
    assert state['请求次数'] == 1
    with pytest.raises(ProbeError, match='重做'):
        generate_next(output, service)
    assert service.calls == 1
```

核心接口固定为上述`prepare_task(photo, output, assets)`、`generate_next(output, service)`、`accept_base(output)`及`ProbeError`；客户端提供`ImageService(key, transport=None).edit(prompt, images)`、`ImageResult(png, usage, request_id)`与`ServiceError(message, uncertain=False)`。准备和生成均返回落盘后的状态字典。执行：

- [x] 步骤2：实现一次请求客户端并让对应测试通过。

客户端接受非空密钥、中文提示及PNG输入字节，返回PNG字节、数字用量和可用的请求编号；测试可注入传输替身，但生产接口地址固定。使用操作系统代理与默认TLS验证，不修改全局设置。禁止自动重试，禁止跟随重定向转发Authorization，响应大小及读取超时有限制。

HTTP错误、连接错误、无效JSON、缺少结果、错误base64及超大响应均输出预定义中文错误；不输出原始响应正文、请求头、输入密钥或原始异常。用量只保存已知数字字段，不原样保存任意远程内容。提交前必须能证明恶意错误正文中出现测试密钥时，终端和文件中均不包含该值。

- [x] 步骤3：实现准备和可恢复任务，并让门槛及恢复测试通过。

固定七姿势：`idle[0]`、`look[4]`、`look[12]`、`waving[1]`、`waving[2]`、`eat_loop[1]`、`supine_sleep[0]`，分别表达待机、左右转头、两个招呼姿势、进食及仰卧。它们只是代表姿势，不声称是完整29组动画。

准备时应用EXIF方向并移除无关元数据，限制照片和像素大小，复制到指定新目录，保存配置与输入校验值。拒绝覆盖已有非空目录，不写源照片或安安素材；任务中的路径限定在其目录内。

实际输入是双猫合照，需在`prepare_task`和CLI `prepare --subject`接受可选目标说明，单猫默认空说明仍可使用。说明限制长度，保存为独立UTF-8输入并纳入现有hash，所有请求使用同一目标说明；本轮明确选前方绿眼棕白狸花，不能混合后方布偶。不做自动识别或裁剪。旧试验任务格式不兼容时清楚提示另建任务，不自动覆盖旧结果。

先生成待机，必须显式accept才能生成其他六张。每次请求前先落盘请求数与“请求中”，崩溃重开按“结果未确认”处理。已完成槽位不重复计费；失败及未知状态只有显式retry才允许再发，任务总请求上限建议10次，正常七张只需7次，不静默增加上限。

使用可随进程退出释放的系统任务锁保护状态修改和请求；同时运行两次工具时，只允许一个取得当前任务，另一个给出中文提示，不重复提交同一姿势。

候选图至少检查可解码、1024画布、可见主体与真实透明通道；整画布等比缩小到256供对照，不应用安安去绿或逐帧包围框缩放。保存原始图、规范化图、中文提示、耗时、数字用量和状态；API返回图像不合格也计入实际请求。
