## 一、附近鼠标感知

### 目标

安安处于清醒静止坐姿时，鼠标从身上移到周围仍能被注意到并触发转头；鼠标不必始终位于透明窗口内。沿用现有十六方向素材、方向死区、迟滞和完整头部绘制。

### 方案比较

| 方案 | 表现与取舍 |
|---|---|
| 附近范围感知，推荐 | 感知周边鼠标，范围随显示大小缩放；设置退出范围和静止超时，兼顾自然活动 |
| 全屏持续跟随 | 容易吸引注意，也容易长时间盯着远处鼠标；持续关注可能压制随机行为 |
| 仅扩展悬停矩形 | 修改简单，但透明窗口周边仍有硬边界，无法自然解释进入退出 |

### 推荐行为

- 以现有窗口中心为参考点，使用 Qt 全局鼠标坐标和逻辑像素，沿用现有定时器读取位置；不安装全局鼠标钩子，不记录移动轨迹。
- 进入半径为显示宽度的 1.2 倍，退出半径为 1.5 倍。默认宽度 220 时分别为 264 和 330 逻辑像素；两者均为到中心的距离。
- 未关注时，鼠标移动进入内圈，且安安为 `idle`，开始跟随。
- 已关注时，鼠标移出窗口但仍在外圈内，继续跟随；超出外圈后平滑回正。内外圈差用于避免边界来回切换。
- 鼠标停止移动约 3 秒后结束关注并平滑回正；需要新的有效移动才再次激活，避免固定在附近的鼠标永久压制随机动作。
- 关注期间延后随机行为，结束后保留现有短暂安静期，之后恢复调度；不清空已有冷却。
- 跳跃、挠耳、睡眠、起卧、拖动及其他动作优先；附近鼠标不打断这些动作，不叫醒安安。
- 右键菜单及大小对话框打开期间暂停附近跟随；关闭后重新判断。
- 鼠标关注不改变鼠标事件区域；周围的桌面仍可正常点击。单击才跳、拖动松手不跳的规则保留。

### 需要验证的边界

- 从猫身上移到附近，跟随不中断；远离后回正。
- 在进入和退出边界轻微移动不反复闪切；中心附近和方向边界不抖动。
- 鼠标静止后关注超时，不会每帧重新激活；随机活动可以恢复。
- 睡眠、拖动、短动作及菜单对话框期间不抢占动作；不会因附近移动产生跳跃。
- 100、220、400 三种大小及不同显示器坐标下，感知距离与方向计算一致。

## 二、挠耳节奏

当前十六帧挠耳总时长为 1,255 毫秒。推荐第一轮将逐帧时长放慢约一倍，总长约 2.51 秒，短过渡也相应调整，使抬爪、轻挠和放爪更从容。该时长是体验起点，不声称是猫咪动作的生理标准。

保留现有独立姿势和前爪对齐，修改播放时间及素材准备脚本中的对应参数，避免重新生成素材时恢复旧节奏。通过播放器生成前后对照预览，并验证完整动作播放、末帧保持、随机冷却与其他动作衔接。

## 三、脚本与成品的职责

| 入口 | 职责 | 环境 |
|---|---|---|
| 成品 `安安.exe` | 直接运行已打包的桌宠 | Windows x64，保留全部配套文件，不需要源码 CMD 或额外 Python |
| `启动安安.cmd` | 自动准备项目依赖并从源码运行 | 已安装 Python；首次需要网络 |
| `制作免安装版.cmd` | 自动准备依赖、测试、构建 EXE 和 ZIP | 已安装 Python；首次需要网络 |
| 计划新增 `下载并启动安安.cmd` | 下载并启动 GitHub 已发布的成品 | Windows x64、系统 PowerShell、网络；不需要 Python |

现有两个脚本继续保留；它们不是过时产物。使用 Git 克隆源码后，已有 Python 的用户可以自行双击构建，不需要再次联系 AI，也不需要重新生成图片。

## 四、推荐的成品分发

源码、素材、测试、依赖和构建脚本进入 Git；成品 ZIP 与校验文件上传到同一 GitHub 仓库的 Releases，不进入源码历史。

直接提交约 39 MiB 的 ZIP 技术上可以做到，但频繁更新的压缩二进制会增加 Git 历史和克隆负担。Releases 用于保存可下载成品，下载入口与源码版本通过标签、校验文件和 `版本.json` 对应。排除 ZIP 的 Git 跟踪不等于不上传成品。

Git 克隆只获取源码，不会自动下载 Releases 附件。用户可选择浏览器下载成品，或使用新增的一键下载入口。下载成品与本地重新构建都不需要 AI 参与。

### 新增下载入口的预期行为

- 仅在用户双击时查询本仓库最新 Release，选择对应的 Windows x64 成品和校验文件。
- 下载、核对 SHA-256、完整解压，确认 EXE 存在后启动。成品缓存放在本机用户数据目录，不写入 Git 源码目录，不覆盖用户偏好。
- 已缓存的版本可继续启动；用户再次获取新版时明确显示版本和结果。具体界面尽量保持为简单的中文脚本提示，不增加账户系统。
- 没有 Release、无法联网、校验失败或文件正被占用时，给出明确中文提示并保留已可用的成品；不自动安装全局 Python，不终止用户其他进程。
- 若同一成品正在运行，提示先退出再更新；不在运行中覆盖程序文件。

## 五、云端构建与发布

现有 `.github/workflows/构建Windows.yml` 已定义主分支推送及手动触发、Windows 测试打包、上传构建产物和创建 Release。实际可用性仍需完整运行验证。

1. 整理当前本地源码、素材及文档，排除虚拟环境、缓存、成品 ZIP 和解压目录，保存可复现的版本基线。
2. 在隔离分支实施本轮交互、节奏和下载入口；本地测试、构建和独立目录启动检查通过后同步源码。
3. 按现有配置，主分支推送会触发云端流程；也可在 Actions 选择“构建安安桌面版”并对 `main` 执行 Run workflow。
4. 检查依赖安装、测试、构建、发布日志。失败时修复实际问题，不以已配置工作流替代运行通过。
5. 成功后核对 Release 标签对应的源码提交、ZIP 的 SHA-256、包内版本信息；从 GitHub 下载附件并验证启动。
6. 面向使用者提供成品 ZIP 的下载入口，明确 `Source code (zip)` 是源码。

本轮源码同步授权已经具备。自动发布属于该工作流在主分支成功构建后的现有行为，向用户说明后按确认的方案执行。新功能使用新版本号发布，不覆盖已经验证的 1.1.0 本地成品。

## 六、验收方式与责任

自动验证由开发过程完成，包括状态机、鼠标感知、挠耳时间、资源、下载校验、构建和独立启动。人工体验保留独立结果，不把自动测试等同于用户认可外观。

用户可先做以下简单操作：

| 操作 | 预期结果 |
|---|---|
| 在 100、220、400 大小间调整并重启 | 大小与位置恢复，画面完整 |
| 靠近、环绕、离开安安，停住鼠标 | 附近自然跟随，离开或静止后回正，不影响桌面点击 |
| 单击、拖动，再要求趴睡和仰卧 | 单击跳、拖动不跳；睡觉时附近移动不叫醒，点击先起身再跳 |
| 右键隐藏、从托盘显示、退出 | 可以恢复，退出后程序结束 |
| 有条件时跨不同缩放比例显示器拖动并断开副屏 | 位置可见，大小与方向正常；没有相应硬件则记为未测 |

无 Python 的另一台电脑验证按用户要求等优化完成后再进行，不作为本轮设计讨论的前置条件。
