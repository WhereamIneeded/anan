# 安安桌面版：构建与使用

## 直接使用

对非技术用户，推荐以下三步：

1. 从 [成品发布页](https://github.com/WhereamIneeded/anan/releases) 下载 Windows ZIP。
2. 右键压缩包，选择“全部解压缩”。
3. 打开解压后的“安安”文件夹，双击 `安安.exe`。

以后继续双击即可，也可以为 EXE 创建桌面快捷方式。请保留整个文件夹，不要只复制单个 EXE。发布页尚无附件时，需先从源码制作成品，不能把源码 ZIP 当成免安装版。简单操作说明也随包保存为 `使用说明.txt`。

成品包含 Python、Qt 和全部动画资源，Windows x64 电脑无需安装 Python、无需图像服务密钥，解压后可离线使用。1.2.0 起成品技术文件名为 `anan-Windows-x64-v版本.zip`，包内仍是“安安”文件夹。程序没有代码签名证书，Windows 可能显示未知发布者提示；这是尚未购买签名证书的分发限制。

## 交互

- 鼠标靠近：清醒静止时安静注视，移出猫咪窗口仍能在周围跟随；不跳跃，也不叫醒睡眠中的安安。
- 普通状态左键单击：跳跃；睡觉时先起身再跳。连续点击不会叠加无限跳跃。
- 按住左键拖动：移动安安，松开不会误触跳跃。
- 右键：调整大小、指定日常动作、趴睡、仰卧睡、叫醒、展示旧动作、隐藏和退出。
- 大小范围 100～400 逻辑像素，默认 220；数值包含动画画布的安全留白，系统缩放仍遵循 Windows DPI。
- 安静模式降低随机活动频率；偶尔散步默认关闭。
- 隐藏后从系统托盘右键选择显示，或单击托盘图标。
- 位置、大小与开关保存在 Windows 用户应用数据目录的「安安/安安桌面宠物」下，独立于源码和原 Pets。

附近鼠标关注的进入半径为显示宽度的 1.2 倍，退出半径为 1.5 倍，均以窗口中心计算；默认宽度 220 时分别为 264、330 逻辑像素。关注期间随机动作延后，鼠标静止三秒或移出范围后平滑回正，再经过短暂安静期恢复调度。菜单、大小对话框、拖动和其他动作期间暂停关注。挠耳完整动作约 2.51 秒。

没有鼠标操作时，安安会间隔一段时间做短动作，也可能趴睡或仰卧睡数分钟，醒来后经过起卧过渡恢复坐姿。重复要求同一种睡姿会继续睡，不会先叫醒再趴下。长时间拖动时走路动画持续循环。程序不自动读取 Codex 或其他应用的任务状态。

## 1.3.2逗猫退出与打招呼

逗猫期间左键双击安安窗口外任意位置即可收起，包含其他软件窗口；不拦截原软件双击。系统时间与位置容差沿用，单击、拖动及猫咪窗口内拍棒不会误退。菜单、大小框暂停，隐藏、切换或退出释放监听，旧会话回调不会结束新一轮。该监听仅为用户已确认的退出手势启用，不读取键盘或其他软件内容。

打招呼由0.76秒延长到2.8秒，复用原姿势轻摆两次，“喵～”与最多三个爱心轻浮、末尾淡出，声音仍默认关闭。哈欠原400～1050毫秒提示保持，普通跳、拖和喂食不变。

[本轮验证记录](2026-10-30-招呼与逗猫退出记录.md)及[下一批玩法建议](下一批趣味玩法建议.md)已保存。

## 1.3.1体态与哈欠

保持较修长的待机和十六方向转头，重画索食、挠耳、舔爪、哈欠、伸懒腰，共38张独立透明帧；动作中保持同一角色尺度，保留自然伸展和低头变化。挠耳2510毫秒及其他既有播放时长保持。

手动右键“打哈欠”或自然触发哈欠时，仅张嘴段约400～1050毫秒显示一次“嗷呜～”，复用输入穿透气泡，声音偏好不变。动作切换、拖动、睡眠、隐藏和退出及时隐藏；菜单或大小框期间隐藏，恢复后不补发过期文字。普通单击跳、索食点击喂食、逗猫点击拍棒保持。

[实际验证和发布记录](2026-10-29-体态与哈欠优化记录.md)区分自动检查、构建成品与人工观感。新素材原件、中文提示、提取记录和连续预览在 `制作/体态统一/`。

## 1.3.0 趣味互动

右键或托盘选择“想吃零食吗”，可立即开始持续撒娇；气泡会提示单击喂一份默认冻干。也可直接选择“喂零食”或“喂冻干”，观看投放、猫碗进食、食物减少和舔嘴满足。完整一轮约 16～27 秒，期间点击不会重复投放或跳跃。

选择“召唤逗猫棒”，在安安附近移动鼠标，它会注视、伸爪；单击猫咪拍棒。离开猫咪窗口仍有效，静止三秒后等待，重新移动继续。选择“收起逗猫棒”或“结束本次互动”可结束。

自动索食默认开启，累计 20～40 分钟清醒可见活动后在安全待机点触发；喂过后间隔 60～90 分钟，未喂而取消后至少 30 分钟。隐藏、睡眠、菜单、大小调整、拖动、安静模式及其他玩法不累计。长时间不响应会降低撒娇频率，不会扣分或强制投喂；不累计离线饥饿。可关闭“自动索食”。

声音默认关闭；可手动打开“猫叫声”，同一索食会话最多两次且至少间隔 60 秒。缺少声音设备时视觉玩法照常进行。音频来自 Kerzoven 的 CC0 素材，来源随资源保存。

拖动、隐藏、指定其他动作、睡觉或开启安静模式会取消当前玩法并清理碗、气泡和玩具。菜单或大小框打开时暂停，恢复后不追赶动画。手动喂睡着的猫或召唤玩具，会先按原路线起身。气泡和玩具使用小型输入穿透窗口，猫碗在原画布内合成。

真实播放器预览和自动检查见[本轮记录](2026-10-29-趣味互动实施记录.md)；用户观感、实际多屏和另一台无 Python 电脑仍需单独验收。

## 公司电脑还原最新版

```powershell
git clone https://github.com/WhereamIneeded/anan.git
cd anan
```

已有仓库先关闭正在运行的开发版，再执行 `git pull --ff-only`。如有自己的未提交修改，先提交或另存，再更新。

源码目录提供三个入口：

- **启动安安.cmd**：双击打开桌宠。首次自动准备运行环境和固定依赖，需要联网；准备完成后，日常启动只检查组件并打开桌宠，不再联网安装、测试或打包。依赖版本变化或组件缺失时自动重新准备；安装失败后重新双击会重试。
- **制作免安装版.cmd**：自动准备依赖、运行测试并打包，成功后打开成品文件夹。把 `dist/anan-Windows-x64-v1.3.2.zip` 发给其他人，对方无需安装 Python。
- **下载并启动安安.cmd**：使用系统 PowerShell 下载本仓库最新兼容 Release 成品，校验、完整解压到 `%LOCALAPPDATA%/安安桌宠/成品缓存` 后启动。无需 Python，首次需要网络；已有有效缓存时，网络失败仍可启动旧版。正在运行时提示先退出再更新，不覆盖运行中的文件。

源码运行与本地构建需要 Windows x64 Python 3.10 或更新版本，推荐 3.10.11。相关脚本优先使用已有 `.venv`，否则使用当前 `python`，最后尝试 `py -3.10`。因此 pyenv 用户选择本目录的 Python 后即可双击，不必安装 Windows Python Launcher，也不用手动创建虚拟环境。直接使用成品或下载入口不需要 Python，成品 EXE 不会调用源码脚本。

旧入口 `启动.cmd` 和 `构建.cmd` 继续可用。准备失败时窗口保留中文提示，详细信息保存在 `build/准备日志.txt`；应用启动错误保存到 `build/启动日志.txt`。请先退出旧版安安再启动更新后的版本。

动画成品已经入库，不需要运行素材制作脚本或再次生成图片。每份成品的 `版本.json` 记录实际源码提交，可与仓库最新提交对照；源码压缩包或缺少 Git 时明确标记提交未知，不阻止打包。`SHA256SUMS.txt` 用于核对下载文件。

## 开发命令

```powershell
python --version  # 确认是所需的 64 位 Python；pyenv 用户可先执行 pyenv local 3.10.11
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m anan_pet
.\.venv\Scripts\python.exe scripts/构建.py
```

运行资源在 `assets/`，程序在 `src/anan_pet/`；设计及实施记录在 `docs/`；新动作的内置 imagegen 提示、源图和预览在 `制作/新增动画/` 与 `制作/趣味互动/`；全部原照和既有素材仍在 `资料/`。

## 云端构建

先确认最新源码、素材和依赖已提交并推送到 `main`。手动运行时打开 [Actions](https://github.com/WhereamIneeded/anan/actions)，选择「构建安安桌面版」，点击 `Run workflow` 并选择 `main`。若页面要求启用 Actions，先按页面提示启用该仓库的工作流。

2026 年 10 月 28 日首次实际云端运行成功，但使用的是尚未同步本地修复的旧提交 `4479636`，生成 1.0.1。它不能证明最新低头、去绿边或本轮交互优化已发布。后续应核对实际源码提交、附件版本、SHA-256 和包内 `版本.json`；1.3.0新版验证状态见[实施记录](2026-10-29-趣味互动实施记录.md)。

GitHub Actions 在主分支更新或手动触发时，用干净 Windows 环境安装精确依赖、运行测试、构建并上传 ZIP。主分支构建成功后，以独立的构建标签创建新版 Release，并将其标为最新版；标签、源码和 ZIP 内的提交号对应。也可在 Actions 的对应运行记录下载构建产物。

公司电脑若不能安装开发工具，直接下载 Releases 的最新成品即可。运行环境、图片和行为逻辑都在成品中。

Git 克隆不包含 Release 附件，也不包含本地 `dist/`；这不妨碍换电脑使用。可以直接下载成品、双击下载入口，或在已有 Python 的电脑双击本地构建入口，均不需要再次联系 AI 或重新生成图片。`Source code (zip)` 是源码，直接运行应选择 `anan-Windows-x64-v版本.zip`。
