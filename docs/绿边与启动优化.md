# 绿边与启动流程优化：1.0.2

2026 年 10 月 23 日，用户在 Windows 启动后反馈猫咪轮廓有明显绿边，并希望非技术人员也能轻松使用。用户本机用 pyenv 的 `.python-version` 选择 Python 3.10.11，没有安装 Windows 的 `py` 启动器。

## 问题与修复

旧素材准备脚本从历史 `qa/frames` 目录复制九种状态，共 57 张图；这些是带绿幕残留的中间帧。最终精灵图已经清理过边缘，但此前只用于提取十六个注视方向。旧坐姿六帧有 9,689 个明显绿溢色像素，其中包含不透明绿色像素，透明窗口会直接把它们显示出来。

准备脚本现改为从已批准的最终精灵图提取全部旧动作。保留 192×208 单格、256×256 运行画布和原有偏移，不逐帧重新缩放或定位。重新运行脚本保留 `animations.json` 中现有的睡眠、新版挠耳及播放时间配置。

最终图集的坐姿首帧还留有 961 个较淡的绿溢色像素。显示前对每个可见像素，将超出红、蓝两通道最大值的绿色通道压低至该最大值，保留透明度和坐标。该处理适用于本角色的白、棕色毛发及蓝灰眼睛，不是通用绿色情景的抠图算法。按唯一文件路径缓存处理后的帧，播放过程不重复处理。全部原始图集、历史资料和原 Pets 保留。

## 面向使用者的入口

- `启动安安.cmd`：已有 `.venv` 优先使用，否则尝试当前 `python`，最后尝试 `py -3.10`；兼容 pyenv 的批处理 shim。首次自动建立环境和安装锁定组件；准备成功后记录依赖签名，日常只验证组件可导入并打开桌宠。依赖变化或组件缺失会重试准备，不在每次启动时跑测试或打包。
- `制作免安装版.cmd`：准备组件、运行测试、打包及启动检查，然后打开成品目录。
- `启动.cmd`、`构建.cmd`：保留为兼容入口，先切换 UTF-8 代码页再调用新入口。
- `使用说明.txt`：面向普通用户的解压、双击、交互和故障反馈说明，并随成品一起分发。

依赖安装失败不会写入成功标记，下次双击可以重试。GUI 进程在后台运行，启动阶段的异常写入 `build/启动日志.txt`，准备及构建错误写入 `build/准备日志.txt`。没有 Python 时明确说明当前是源码版，指引用户使用免安装版；不会自动下载或安装全局 Python。源码压缩包缺少 Git 元数据时仍可构建，`版本.json` 会标明提交未知。

## 本次验证

- 两项素材回归先失败后通过：检查 57 帧与最终图集逐像素一致，以及重新生成时完整保留已有动画配置。
- 两项显示回归先失败后通过：检查实际窗口缓存中的坐姿无绿溢色，且棕色毛发、蓝灰眼睛、粉色与透明度保持。
- 启动准备逻辑覆盖首次创建、离线重启跳过安装、依赖变化、组件缺失修复、安装失败后重试、后台进程立即退出时的错误反馈。

- 原始资料 329 个文件、15 张原照校验通过。
