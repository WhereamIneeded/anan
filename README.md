# 安安 · Windows 桌面宠物

以真实布偶猫安安为原型的独立桌宠，保留原 Pets 的形象与动作，增加自主日常行为。原 ChatGPT Pets 安安保持不变。

**当前源码版本1.3.2：逗猫棒期间双击安安窗口外任意位置即可退出，打招呼延长到2.8秒，并增加“喵～”和浮动爱心。** 声音默认关闭，保留1.3.1修长体态及哈欠文字。实现、实际验证与发布状态见[本轮记录](docs/2026-10-30-招呼与逗猫退出记录.md)。

动作使用独立的对齐点、循环方式和切换时间；睡眠明确划分进入、保持、退出阶段。转头从当前画面短过渡，长拖动继续播放走路，重复要求睡觉不会先叫醒；悬停时延后随机行为。保留去绿边、完整低头姿势、双击启动和十六帧挠耳。详见[本次优化说明](docs/动作配置与衔接优化.md)及[启动说明](docs/构建与使用.md)。

## 使用与功能

解压整个成品文件夹，双击 `安安.exe`。成品包含 Python、Qt 和动画，可离线运行。

大小 100～400，默认 220 逻辑像素；附近注视不跳，单击跳，拖动不误触。随机挠耳、舔爪、哈欠、伸懒腰、环顾、趴睡和仰卧睡；睡觉有进入、保持、翻身和起身过渡。睡眠中点击先起身再跳。支持托盘、安静模式、可选散步、偏好保存与屏幕位置恢复。

清醒静止时，鼠标移动到安安身上或周围即可引起关注，移出猫咪窗口仍能跟随。默认大小下，进入和退出感知范围分别约为距中心 264、330 逻辑像素，随大小缩放。鼠标停住三秒或离开范围后平滑回正，之后恢复随机活动。睡眠、挠耳、跳跃、拖动及打开菜单或大小对话框时不抢占动作。挠耳保留十六个连续姿势，完整时长约 2.51 秒。

## 1.3.2交互优化

逗猫棒互动期间，快速左键双击安安窗口以外的任意位置（包括浏览器、文件夹等其他软件）可收起逗猫棒并恢复普通状态；原软件仍照常收到双击。单击或拖动不作为退出手势，安安窗口内点击仍拍棒。监听只在该玩法可交互时启用，菜单或大小框暂停、隐藏、切换和退出时释放；系统的双击时长与位置容差继续沿用。

“打招呼”播放约2.8秒，抬爪轻摆再收回，出现一次“喵～”气泡与少量浮动爱心，末尾淡出。声音默认关闭，其他动作可以打断。哈欠“嗷呜～”和普通点击跳、拖动、喂食规则保持。

[下一批玩法建议](docs/下一批趣味玩法建议.md)推荐摸摸、自然行为衔接、纸箱和小球；这些尚未实现，没有自动加入本轮。

## 体态与哈欠文字

以既有较修长的待机为基准，重画索食、挠耳、舔爪、哈欠和伸懒腰，保留同一只猫的骨架尺度、头胸比例、毛色与尾巴体积。低头和伸爪等自然姿态变化继续保留，动作源图和中文提示见 `制作/体态统一/`。

哈欠张嘴的约0.4～1.05秒出现“嗷呜～”短气泡，每次动作一次；切换、拖动、隐藏、睡觉、菜单和大小框暂停时及时隐藏，恢复后不补发过期文字，不新增叫声。普通状态单击、喂食与拍棒规则不变。

真实Qt前后对照和连续GIF保存在 `制作/体态统一/窗口预览/`，供检查同尺寸动作衔接；用户观感与真实多屏仍需体验确认。

## 趣味互动

右键安安或托盘图标即可体验，无需等待自动触发：

- **想吃零食吗**：开始撒娇索食，显示“点我喂一份”的气泡和音符。单击安安喂一份默认冻干；也可从菜单选择“喂零食”或“喂冻干”。
- **猫碗进食**：投放、低头吃、食物分级减少、抬头舔嘴满足，完整一轮约 16～27 秒。进食时连点不会重复投放或跳跃。
- **召唤逗猫棒**：羽毛棒跟随全局鼠标；在安安附近移动可引起注视和伸爪，单击安安拍棒。鼠标停住三秒后等待，继续移动还可逗；菜单可收起。
- **自动索食**：默认开启，累计 20～40 分钟清醒可见活动后，在空闲安全点触发；吃过后间隔 60～90 分钟，未喂而取消后至少 30 分钟。不累计离线时间。
- **长期撒娇**：不响应时会话持续，前 60～90 秒较明显，随后约每 20～40 秒轻量表达。可随时选择“结束本次互动”，也可关闭自动索食。
- **猫叫声**：默认关闭；主动开启后同一索食会话最多两次、至少间隔一分钟。气泡和动作不依赖声音设备。

普通状态单击仍跳跃。拖动会结束玩法，松手不会误喂；隐藏、睡觉、切换活动或开启安静模式会清理本次玩法。菜单和大小对话框打开时暂停，关闭后继续。睡着时手动喂食或逗猫，先按原路线起身。羽毛棒和气泡是穿透输入的小装饰窗，不提供全屏点击层。

## 公司电脑获取最新版

首次执行 `git clone https://github.com/WhereamIneeded/anan.git`，进入仓库；已有克隆先保存本地修改，再执行 `git pull --ff-only`。

已装 Windows x64 Python 3.10 或更新版本的电脑，双击 `启动安安.cmd` 即可；首次自动准备依赖，以后直接启动。支持 pyenv 当前选中的 Python，无需另外安装 `py`。双击 `制作免安装版.cmd` 可测试并打包，完成后自动打开成品文件夹。旧的 `启动.cmd`、`构建.cmd` 仍可使用。

没有 Python、但已经克隆源码的电脑，可双击 `下载并启动安安.cmd`，由 Windows 自带 PowerShell 获取本仓库最新兼容成品，校验 SHA-256、解压到本机应用数据目录并启动。首次需要网络与可用 Release；有已验证缓存后，网络失败仍可使用旧缓存。更新时请先退出正在运行的缓存版本。

| 使用场景 | 入口 | 所需环境 |
|---|---|---|
| 使用已经打包好的桌宠 | 完整解压成品 ZIP，双击 `安安.exe` | Windows x64，无需安装 Python |
| 已克隆源码，只想获取成品使用 | `下载并启动安安.cmd` | Windows x64 与系统 PowerShell；首次联网下载可用 Release，无需 Python |
| 从源码运行、修改后立即体验 | `启动安安.cmd` | 已安装 Windows x64 Python 3.10 或更新版本；首次联网准备项目依赖 |
| 从源码重新制作免安装包 | `制作免安装版.cmd` | 同上；自动准备依赖、测试并调用 PyInstaller 打包 |

源码启动与制作成品的两个 CMD 是开发项目的现役入口，新增的下载入口方便直接获取成品。成品中的 `安安.exe` 不会调用这些脚本。换电脑从完整源码构建时不需要重新联系 AI，也不需要重新生成图片；全部运行素材已在仓库中。尚未安装 Python 的电脑优先使用发布页的成品或下载入口。

给非技术用户的步骤见 [使用说明.txt](使用说明.txt)。成品 ZIP 无需安装开发工具。`版本.json` 记录源码提交；从源码压缩包构建时会明确标记提交未知。

## GitHub 构建和发布

仓库已配置 `.github/workflows/构建Windows.yml`：主分支推送或手动触发后，GitHub 的 Windows 构建机安装锁定依赖、执行测试、生成 ZIP；主分支成功后创建 Release 并上传 ZIP 与校验文件。该流程是否成功必须以实际运行记录为准。

需要手动运行时：

1. 先确认最新源码、素材、依赖及构建脚本已经提交并推送到 `main`。
2. 在 GitHub 打开仓库的 **Actions**，选择“构建安安桌面版”。
3. 点击 **Run workflow**，选择 `main`，再次点击 **Run workflow**。
4. 等待流程完成；失败时打开对应步骤查看日志，不将失败记录当作已发布。
5. 成功后打开 **Releases**，在对应版本的 **Assets** 中下载 `anan-Windows-x64-v版本.zip` 及 `SHA256SUMS.txt`。
6. 核对校验值与包内 `版本.json` 的版本、源码提交；完整解压后双击 `安安.exe`。

GitHub 自动提供的 `Source code (zip)` 是源码快照；直接运行请下载名称为 `anan-Windows-x64-v版本.zip` 的成品附件。成品 ZIP 不加入源码 Git 历史，不影响将它上传到同一仓库的 Releases。
